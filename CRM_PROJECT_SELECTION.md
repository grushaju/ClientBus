# Выбор проекта DIKIDI — 12.4.8

07.11.2026 по запросу пользователя ввод внешнего ID заменён выбором из списка проектов выбранного аккаунта. 08.11.2026 отдельное поле поиска убрано: проекты выбираются непосредственно в выпадающем списке. После выбора остаются проверка проекта, настройка часового пояса и отдельное подтверждение привязки либо восстановления архива.

## Доступность и занятость

`GET /api/crm/connections/{connectionId}/projects?workspaceId={workspaceId}` возвращает массив `CrmProjectCheckDto` с внешним ID и названием. Сам список не подтверждает валюту/часовой пояс: они уточняются прежним `project-checks` перед подключением. Доступ — SUPER_ADMIN своей Organization с доступом к указанному Workspace. Credentials и права повторно проверяются после внешнего чтения, выполненного без транзакции БД.

Из списка исключаются проекты, уже привязанные в этой Organization, независимо от того, каким аккаунтом их подключили. Выключенное обновление продолжает занимать привязку. Если целевой Workspace уже занят проектом DIKIDI, свободных вариантов для него нет. Архив того же Workspace можно выбрать с пометкой «восстановить»; архив другого Workspace исключается, поскольку сохраняет исходную границу истории и уникальную идентичность проекта. Сама операция bind по-прежнему проверяет занятость и уникальный индекс: обновление списка не служит разрешением на подключение.

При смене аккаунта выбранный проект сбрасывается и старый запрос отменяется. Поздний ответ не заполняет список другого аккаунта. Есть состояния загрузки, ошибки с повтором и отсутствия свободных проектов. Обновить список можно вручную. `crm.invalidated`, создаваемый обновлением health аккаунта, не запускает повторный внешний запрос списка; актуальные локальные привязки дополнительно исключаются на клиенте.

Первоначальная загрузка настроек отделена от фонового обновления: после успешного чтения форма и селектор остаются смонтированными, включая повтор после временной ошибки. Выбор и подтверждение проекта сохраняются. Фоновое чтение локальных привязок не отключает поля выбора аккаунта и проекта; проверка/подключение блокируются до завершения обновления. После ошибки локального чтения поля и действия блокируются до успешного повтора. Отзыв доступа очищает настройки, скрывает форму и отменяет запрос вариантов. Это устраняет цикл «чтение DIKIDI → health-событие → обновление родителя → повторное монтирование селектора → чтение DIKIDI».

Внешний список вариантов исключён из общих reconciliation при `stream.ready`, fallback/control polling и восстановлении видимости/сети (`reconcile: false`). Начальное и ручное чтение, адресные события изменения доступа и немедленный revoke сохраняются. Обычные подписки, включая нотификации и локальные привязки CRM, продолжают обновляться. Это предотвращает повторную авторизацию/чтение DIKIDI и отключение раскрытого селектора каждые 10–12 секунд в fallback-режиме.

## Подтверждённое чтение DIKIDI

В авторизованной навигации найдена страница `GET https://dikidi.ru/ru/business/projects`. На ней проверяется настоящая форма `form.new-elements-list.projects` с action `/ru/business/ajax/projects/list/` и `data-method=post`. Публичный каталог компаний не используется.

Список читается через `POST /ru/business/ajax/projects/list/` с `offset`, `limit=10`, `more=1`. Ответ должен иметь `append=".project-list"` и строковый `html`. В карточке `div.new-elements-content-block.list-item.project` совпадают `data-id` и параметр `company` ссылки `a.name` на `/ru/owner/`; её текст даёт название. Ссылки не открываются, обработчики и скрипты не выполняются. Неоднозначные/повторяющиеся ID, чужой target, неизвестная разметка и усечённая карточка отвергаются.

Подтверждены два разных конца списка: пустой аккаунт возвращает `stub-custom` с точным заголовком «По вашему запросу ничего не найдено»; после непустой страницы терминальная порция содержит whitespace HTML. Начальный пустой HTML не принимается за пустой аккаунт. Смещение увеличивается на число принятых строк; повтор ID, превышение лимита порций/строк или ошибка прерывают всё чтение без выдачи частичных вариантов. Общий deadline и блокировка сессии адаптера сохраняются.

`CrmConnectionPort.listProjects` по умолчанию возвращает CAPABILITY_UNVERIFIED для остальных адаптеров; DIKIDI реализует чтение. `LIST_PROJECTS` отмечен реализованным только для DIKIDI.
