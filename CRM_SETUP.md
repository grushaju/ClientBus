## Ключ и запуск

Для текущего локального рабочего каталога постоянный ключ уже создан в `server/data/crm-secrets.properties`. Файл исключён из Git существующим правилом `/server/data/`; его содержимое не копируется в ресурсы/JAR. Spring Boot импортирует его при запуске из корня ClientBus и из модуля server. Этот файл нужно сохранять между перезапусками; после первой настройки перезапустите `ServerApplication`.

В других окружениях задайте в окружении запуска server постоянный `CLIENTBUS_CRM_SECRET_KEY`: Base64 от 32 случайных байт. `CLIENTBUS_CRM_SECRET_KEY_ID` по умолчанию `primary`; идентификатор также должен сохраняться между запусками. Переменные окружения имеют приоритет над локальными значениями файла.

Ключ генерируется один раз и хранится вне Git в локальном файле или настройках окружения/секретов запуска. Новый случайный ключ при каждом старте не позволит прочитать ранее сохранённые пароли. Автоматическая ротация ключей пока не реализована. Без ключа остальная система запускается, а сохранение подключения возвращает `409 CRM_CONFIGURATION_REQUIRED`. Пароль DIKIDI хранится AES-256-GCM с привязкой к Organization, connection UUID и key ID; публичные DTO возвращают только маску телефона и признак наличия секрета. Cookies/CSRF остаются в памяти адаптера.

Локальная настройка проверена отдельным запуском Spring Boot без БД/DIKIDI: из обеих рабочих директорий ключ загружается как 32 байта, AES-GCM roundtrip успешен. Значение ключа при проверке не выводится.

Для создания схемы нужен существующий DB-пользователь с правами DDL. Конфигурация Flyway создаёт `dbo`, `system`, `crm`; существующие миграции не изменены и новые не добавлены. Hibernate `ddl-auto=update` создаёт шесть CRM-таблиц: connection/project/master/syncstate из 12.3 и service/masterservice из 12.4.1; core-таблицы остаются в `dbo`. После JPA проверяется частичный уникальный индекс `crm.uqprojectdikidiworkspace`; неправильный существующий индекс останавливает запуск, а не допускает некорректные привязки. Физические CRM-имена не содержат подчёркиваний.

## UI и права

Ниже описан реализованный UI 12.3/12.4.1. Согласованный 02.11.2026 [новый макет](ui/mockups/12-crm-settings.html) входит в UI-дополнение 12.4.1 и перенесён в приложение 03.11.2026: аккаунты остаются в настройках организации, привязки — в Workspace, а рабочий каталог и отдельные связи для руководителей доступны в основном разделе CRM. Статус и критерии переноса — [Stage 12.txt](Stage%2012.txt) и [эргономическое ревью](ui/mockups/12-crm-ergonomics-review.md).

1. SUPER_ADMIN открывает «Настройки → CRM», вводит телефон/пароль DIKIDI, сохраняет подключение и нажимает «Проверить». Пароль очищается из формы при отправке и не записывается в browser storage.
2. В CRM-панели выбранного Workspace вводит ID проекта, при необходимости явно задаёт IANA timezone, нажимает «Проверить проект», затем «Привязать проект». Preview не создаёт проект/мастеров. После привязки запускается отдельное свежее чтение каталога мастеров, услуг и предложений. Та же панель доступна SUPER_ADMIN в карточке Workspace.
3. SUPER_ADMIN или супервизор Workspace вручную выбирает Employee для мастера. Обычный сотрудник видит сохранённых мастеров и состояние обновления без управления сопоставлениями и учётными данными. Импорт не создаёт Employee и не выдаёт ему права.
4. «Обновить» в основном разделе CRM запускает внешнее чтение CATALOG. Локальные данные перечитываются автоматически после действий и invalidation. Недоступность провайдера сохраняет предыдущие профили, links и последнее успешное наблюдение. Частичный ответ не удаляет отсутствующих мастеров и не получает CURRENT/COMPLETE.
5. Часовой пояс, выключение проекта и смена подключения изменяются с проверкой версии. Смена подключения сохраняет UUID проекта и ручные links. Повторная привязка того же проекта к другому Workspace запрещена, включая отключённую привязку. Workspace с проектом не удаляется; удаление Employee снимает допустимый необязательный link, а авторская ссылка защищается ответом 409.

Ошибки DIKIDI не возвращают локальный 401 ClientBus: необходимость повторной авторизации провайдера имеет отдельный `CRM_REAUTH_REQUIRED`. Права на Organization/Workspace проверяются по актуальной БД. Смена аккаунта/Workspace и отзыв доступа отменяют старые UI-запросы; поздние результаты загрузки проверяют connectionId, credentialVersion, contextVersion, zoneRevision и действующий CATALOG claim перед применением.

Смена UI-контекста отменяет также незавершённое действие формы и очищает busy/черновик, даже если компонент остаётся на той же странице Settings/WorkspaceDetails. Старый ответ не блокирует новую операцию. Backend читает мастеров и состояние их загрузки одним согласованным снимком; порядок блокировок настройки, импорта и Employee links проверен конкурентными сценариями PostgreSQL, включая аудит удаления.

## Ограничения нагрузки

Значения по умолчанию: connect timeout 5 секунд, HTTP request timeout 15 секунд, тело ответа до 4 MiB. Они настраиваются через `clientbus.crm.connect-timeout-ms`, `request-timeout-ms`, `max-response-bytes`. Полное действие адаптера ограничено 75 секундами; не более четырёх HTTP-вызовов одновременно. Сессии изолированы по connection UUID и credentialVersion, максимум 128, idle TTL 20 минут. Загрузчик имеет два worker без очереди; повторная загрузка активного проекта объединяется, перегрузка возвращает 429. Lease CATALOG — 120 секунд по часам БД. Это ограничения ClientBus; лимиты частоты самого DIKIDI не установлены.

`crm.invalidated` использует существующий outbox/SSE: organization для аккаунтов, workspace для каталогов и обновляет CRM-панель с coalescing. Дополнительные payload-поля projectId/datasets/period ещё не реализованы. Персональные уведомления на каждую импортированную строку не создаются.

## Каталог 12.4.1

Исправление обновления названия 05.11.2026: название внешнего проекта раньше сохранялось только при привязке и смене подключения. Теперь каждая загрузка CATALOG перечитывает профиль DIKIDI и сохраняет актуальное название вместе с каталогом. В разделе CRM кнопка «Обновить» запускает эту загрузку сразу. Автоматический запуск включён для подключённых проектов, включая старые проекты без CATALOG-state: `clientbus.crm.catalog.enabled=true`, `clientbus.crm.catalog.refresh-ms=300000`, `clientbus.crm.catalog.poll-ms=10000`. Для запуска нового кода нужен перезапуск server. Название Workspace не меняется.
