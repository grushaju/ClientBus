# 12.5 — интерфейс просмотра CRM

Реализовано 08.11.2026 по согласованному [CRM_UI_PLAN.md](CRM_UI_PLAN.md). Основой служат существующие серверные проекции 12.4. Экран не создаёт чатовый канал DIKIDI и не выполняет создание, перенос или отмену внешних визитов: это 12.6.

## Где смотреть

- `/crm?tab=clients` — клиенты CRM: серверный поиск, фильтр «Без связи с ClientBus», страницы и карточка клиента. Первая связь и атомарное создание ClientBus подтверждаются явно. Замена/снятие связи доступны управляющему Workspace или администратору; архив доступен только для просмотра.
- `/crm?tab=appointments` — вкладка CRM «Записи», общий выбор Workspace и проекта, активный проект по умолчанию, архивные проекты с пометкой. Даты, мастер, клиент CRM, вид и состояния записи задаются URL-параметрами и сохраняются при переключении вкладок. Разрешён период 1–31 день. Служебные блоки, резервы и неизвестный вид отличимы от визитов. Отдельного пункта «Записи» в меню нет. Маршрут `/appointments` удалён.
- Карточка записи — исходное местное время и часовой пояс, исторические услуги/цены и мастера, статусы, комментарий и предупреждения. Финансовый блок читает сохранённые данные при раскрытии; явное обновление использует существующий read-only FINANCE-сценарий. Неизвестные суммы не становятся нулями, неподтверждённая полнота отображается явно. Для архива/отключённого проекта обновление не предлагается.
- `/crm?tab=schedule&master={локальный UUID}` — рабочие интервалы одного выбранного мастера и точного периода. Есть поиск/страницы мастеров, неделя/день и явное обновление. Рабочие часы не объявляются свободными слотами для бронирования. Ссылка доступна из карточки мастера.
- `/clients/{id}` → «CRM и визиты» — раскрываемый блок связей с внешними карточками, прошлых/будущих визитов и ручного периода. По умолчанию выбран текущий Workspace; доступен объединённый просмотр разрешённых Workspace. Обновление истории выполняется явно для выбранной внешней карточки и периода.
- Панель клиента Inbox → «CRM и визиты» — только Workspace диалога, до трёх ближайших строк, карточка визита и переход в `/crm?tab=appointments&clientId=...&workspace=...`. Полный список учитывает все связанные CRM-карточки ClientBus этого Workspace. Без связи аккаунта канала с ClientBus используется существующая привязка клиента, фиктивная связь с CRM не создаётся.

## Данные и права

Добавлен локальный GET: `/api/crm/clientbus-clients/{id}/links?workspaceId=...`. Он возвращает `CrmClientLinkDto {client, project}`. ClientBus должен принадлежать текущей Organization; явно заданный Workspace проверяется до выборки. При объединённом запросе недоступные Workspace исключаются из результата. Архивные связи остаются читаемыми. Метод не вызывает DIKIDI, не меняет связи и не раскрывает credentials.

Выбор клиента в «Записях» использует второй локальный GET `/api/crm/projects/{id}/appointment-clients` с точным периодом. Поиск и пагинация работают по сохранённым визитам, даже когда справочник `crm.client` пуст. В URL сохраняется `externalClientId`; прежние переходы с `crmClientId` поддержаны. Исторические имена не используются для объединения людей: доступны только подтверждённые PROJECT identity из APPOINTMENT. Вызовы DIKIDI и создание клиентов/связей не добавлены. При изменении периода варианты перечитываются; при смене проекта внешний ID сбрасывается. Одно обновление периода публикует одно итоговое событие вместо события на каждую страницу. После 202 UI сразу перечитывает локальное состояние запроса.

UI использует существующие GET клиентов, кандидатов, графиков, записей, агрегированной истории и финансового снимка. Клиентские страницы адаптируют `syncState` к общей загрузке страниц. Ревизия визитов остаётся строковым токеном; она не преобразуется в число. Coverage показывается по точным scope/проектам, наличие строк не повышает полноту.

Для смены/снятия связи и создания клиента отправляется версия, зафиксированная при открытии действия. Фоновое обновление не подставляет новую версию в уже подтверждаемую операцию. Кандидат виден в подтверждении по имени и телефону. Повторная отправка заблокирована синхронно; конфликт закрывает подтверждение и перечитывает карточку.

При отзыве доступа запросы и команды отменяются, недоступные проекции скрываются, поздние ответы не возвращают прежние данные. Изменение выбора/периода/клиента создаёт отдельного владельца запроса. Фоновое чтение сохраняет форму и доступные данные, раскрытые элементы не зависят от `loading`. Отключение/архив не стирает локальную историю. У архива не показывается выполняющееся обновление, даже если старое состояние scope было QUEUED/RUNNING.

Блоки в карточке клиента и диалоге читают CRM только при раскрытии; скрытая панель диалога не запускает эти чтения. В ближайших/прошлых визитах принадлежность определяется по подтверждённому UTC-времени. Строки без такого времени сохраняются с явным предупреждением, без догадок по часовому поясу браузера. Ручной период показывает все визиты выбранных дат.

После ревью 12.5 компактный блок догружает страницы, пока не найдены три подходящих визита или не исчерпан результат. Ошибка останавливает догрузку, скрытие панели отменяет запрос. Автоматический период будущего начинается с самой ранней сегодняшней даты среди проектов, прошлого — заканчивается самой поздней; оба включают текущий местный день каждого проекта и соблюдают лимит 31 день. Смена проекта в «Записях» сохраняет ClientBus-клиента, даты и состояния; сбрасываются только UUID мастера и CRM-клиента прежнего проекта.

Фильтры мастера и клиента CRM объединяют выбор и поиск в одном выпадающем поле. «Все клиенты» означает отсутствие фильтра по клиенту; поиск внутри списка только сужает варианты, выбор применяется явно. Список загружается при раскрытии. Фоновое обновление сохраняет открытый список, поиск и фокус; загрузка, ошибка, отсутствие сохранённого справочника и пустой результат поиска отображаются внутри выпадающей области и не сдвигают фильтры. Поддержаны клавиши стрелок, Enter, Escape и закрытие при уходе фокуса/нажатии снаружи. Tab пропускает варианты списка; при удалении активного варианта или кнопки последней страницы фокус возвращается в поиск. Кнопка догрузки сохраняет фокус во время запроса, повторная отправка заблокирована. После ухода в другой фильтр поздние ответы не перехватывают фокус.

## Проверки

Порядок вкладок подтверждён пользователем 08.11.2026: «Записи», «Мастера», «Услуги», «Клиенты», «График». Код и тест соответствуют этому порядку. Ширина страницы и полоса прокрутки стабильны; скрытые действия шапки сохраняют место, отступы содержимого не схлопываются наружу. Браузерная регрессия сравнивает координаты и ширину заголовка, шапки, вкладок и панели при переключении короткого графика и длинного списка записей на desktop/mobile.

- 189 серверных тестов без ошибок/пропусков: 164 PostgreSQL/Testcontainers и 25 HTTP-проверок (22 CRM-контракта и 3 маршрутизации SPA). Проверены локальные CRM-связи, свой/чужой Workspace и Organization, отсутствие доступа и архив, клиенты периода без справочника, поиск/пагинация/внешняя identity и одно итоговое событие многократного импорта/ошибки. Регрессия повторного ревью проверяет одинаковое покрытие CLIENT_HISTORY при выборе клиента по внешнему ID и локальному UUID, без включения истории другого клиента. Логи: `server/target/crm-coverage-review.log` и `server/target/crm-spa-routing-review.log`. Прямое открытие `/crm?tab=appointments` проверено с настоящей цепочкой SecurityConfig без JWT-заголовка; API остаётся закрыт, удалённый маршрут записей возвращает 404 авторизованному пользователю.
- 473 UI-теста без ошибок/пропусков. Новые 23 сценария покрывают явное подтверждение первой связи, права на существующую связь/архив, зафиксированную версию при фоне, создание одним запросом, отмену команды при revoke, несколько исторических услуг/мастеров, ленивое чтение финансов, UNKNOWN, служебный блок, границы периода, ближайшие визиты и компактный scoped-блок. Регрессии ревью проверяют догрузку, остановку при ошибке/скрытии, сохранение параметров при смене проекта, историю разных часовых поясов, поиск/выбор в выпадающих фильтрах при фоне, клиентов из визитов периода без справочника и перечитывание состояния после 202. Проверено сохранение фильтров при выборе проекта в общей CRM. Лог: `ui/node_modules/.cache/crm-stable-tabs-ui.log`.
- 48 Playwright-проверок CRM desktop/mobile прошли, в том числе 24 новых запуска экранов 12.5. Проверены клиенты и подтверждения, создание ClientBus, график, карточка записи и неизвестная оплата, ошибочный период, история, компактная панель Inbox и переход к агрегированным записям. Отдельные сценарии обновляют период и отправляют SSE при открытом поиске клиента: проверяют сохранение фокуса/поиска, отсутствие смещения полей, явный выбор/сброс и управление с клавиатуры. Проверены догрузка последней страницы, выход по Tab, восстановление фокуса после удаления активного варианта, сохранение фокуса существующего варианта и отсутствие его перехвата после ухода. При пустом справочнике CRM клиенты из визитов доступны для выбора и фильтруют записи; смена даты меняет варианты. «Записи» открываются во вкладке CRM, фильтры сохраняются между вкладками и после reload; прежний маршрут удалён. Существующая проверка плотности первого экрана сохранена: мобильные отступы вкладок уменьшены, кнопка связей помещается в ту же строку. Лог: `ui/node_modules/.cache/crm-stable-tabs-e2e.log`.
- Скриншоты новых карточек и графика просмотрены. Переполнения по горизонтали в проверенных сценариях нет. Типы e2e и production build прошли. Последующее разделение страниц через React.lazy устранило предупреждение Vite о размере общего JS-bundle; каркас приложения, авторизация и SSE остаются вне границ загрузки страниц.

Браузерные сценарии используют API-фикстуры; серверные — настоящую тестовую PostgreSQL. Новых живых вызовов DIKIDI в 12.5 не выполнялось, рабочие данные не менялись. Ручная оценка интерфейса в запущенном приложении и итоговая живая приёмка остаются отдельными проверками. Сборка переносится в server через `mvn -o process-resources`, последний лог `server/target/crm-stable-tabs-resources.log`. Изменился серверный API, для проверки в приложении требуется перезапуск сервера.

Полное ревью всех незакоммиченных изменений 08.11.2026, включая новые файлы: новых подтверждённых функциональных ошибок не обнаружено. Исправлены устаревшие описания отдельного раздела «Записи» в CRM_SETUP.md и CRM_UI_PLAN.md. Повторно прошли 189 серверных тестов, 473 UI-теста и 46 браузерных сценариев; типы e2e и production build успешны, все 46 файлов сборки совпадают с ресурсами сервера по SHA256. Логи: `server/target/crm-full-review.log`, `ui/node_modules/.cache/crm-full-review-ui.log`, `ui/node_modules/.cache/crm-full-review-e2e.log`.

Повторное полное ревью 08.11.2026, включая ленивую загрузку страниц: исправлена рассинхронизация Workspace и URL CRM при переключении через шапку. Адрес получает новый Workspace, прежние ID проекта/мастера/CRM-клиента очищаются, период и общие условия сохраняются. Переходы между вкладками больше не возвращают прежний Workspace; история браузера восстанавливает соответствующий контекст. Также устранён повторный запрос списка при каждом новом условии после первого обновления периода: новая область выполняет одно первоначальное чтение, а следующее явное обновление — одно повторное. Оба замечания воспроизведены регрессионными тестами до исправления.

Результат повторной проверки: 189 серверных тестов (164 PostgreSQL/Testcontainers и 25 HTTP) и 474 UI-теста прошли без ошибок и пропусков. В общем браузерном прогоне прошли 102 сценария; два сценария порядка вкладок после синхронизации теста с текущей правкой рабочего файла отдельно прошли на desktop/mobile — всего проверены 104 сценария. Логи: `server/target/full-review-final-server.log`, `ui/node_modules/.cache/full-review-final-ui.log`, `ui/node_modules/.cache/full-review-final-e2e.log`, `ui/node_modules/.cache/full-review-tab-order-e2e.log`. Maven завершился ошибкой только после успешных серверных тестов: offline-режиму недоступны незакэшированные зависимости генератора HTML-отчёта. Типы e2e, production build и отдельный `mvn -o process-resources` успешны; все 68 файлов UI совпадают с ресурсами сервера по SHA256.

## Что осталось для завершения 12.5

Обязательных незакрытых задач реализации после ревью не зафиксировано. Остаётся ручная приёмка текущего приложения: записи и фильтры/карточка/финансы, клиенты и сопоставления, график мастера, история ClientBus и компактный блок Inbox; переключение Workspace и ролей, сохранение состояния при фоновых обновлениях. Результат и возможные замечания нужно записать в этот протокол; найденные дефекты устранить до закрытия этапа. Новый живой интеграционный прогон DIKIDI и общая приёмка этапа 12 относятся к 12.7.

Коммит и push не выполнялись. Локальный коммит — по отдельному поручению пользователя. Следующий этап реализации — 12.6, после согласования его подробного плана.
