# Inbox: регрессия и приёмка 10.10

Проверка выполняется после коммита `d8d7ffe` (этап 10.9).
Автоматические проверки и ручная приёмка учитываются отдельно: успешный запуск
тестов не означает завершения браузерных сценариев.

## Повторяемый прогон

Из корня проекта, PowerShell:

```powershell
npm --prefix .\ui test
npm --prefix .\ui run test:e2e:types
npm --prefix .\ui run test:e2e
mvn -o -pl server -am test-compile surefire:test
npm --prefix .\ui run build
mvn process-resources
```

Каждую следующую команду запускать только после успешного завершения предыдущей.
Для серверных интеграционных тестов нужен Docker с доступными образами PostgreSQL
и Kafka, для offline-режима Maven — предварительно загруженные зависимости.
При первом запуске без кеша убрать `-o`.

`npm test` собирает все `*.test.cjs` из `ui/tests`, включая Inbox, сотрудников,
переписку и подробности клиента. Поддерживающие модули не считаются тестами.
Серверный прогон не ограничен наборами 10.7–10.9: он включает коннекторы,
Kafka, репозитории, права, фильтры и запуск Spring-контекста.

Все наследники `AbstractIntegrationTest`, включая `ServerApplicationTests`,
используют профиль `test` и тестовые контейнеры. Проверка запуска приложения
не должна подключаться к БД и Kafka из обычного `application.yml`.
После каждого интеграционного класса Spring-контекст закрывается, пока общий
Kafka-контейнер ещё работает: клиенты Kafka не должны задерживать завершение JVM.

Используется `test-compile surefire:test`: эти цели компилируют приложение и тесты
и запускают весь набор; генерация HTML-отчёта и запуск отдельного сервера из
других фаз Maven в этот прогон не входят. XML-результаты находятся в
`server/target/surefire-reports`.

В ходе регрессии исправлены:

- Подключение `ServerApplicationTests` к обычной БД: класс переведён на общую
  интеграционную базу, тестовый профиль закреплён на базе.
- Шесть проверок, зависевших от пустых общих таблиц: репозиторий аккаунтов
  проверяет точный состав с учётом прежних записей и предикат фильтрации,
  идемпотентность сообщений — число сообщений своего диалога, отказ по неизвестному
  каналу — отсутствие изменений относительно исходных счётчиков.
- Закрытие Kafka producer при завершении JVM: Spring-контексты закрываются
  после каждого интеграционного класса, до остановки тестовых контейнеров.
- Маршрутизация DLQ: все DLQ настроены с одним partition, поэтому обработчик
  ошибок отправляет туда в partition 0. Прежнее сохранение номера исходного
  partition приводило к тайм-ауту для 1 и 2. Три новых unit-сценария проверяют
  исходные partition 0/1/2 и сохранение их номера в заголовках. Интеграционный
  сценарий принудительно отправляет ошибочное сообщение через partition 2
  и проверяет получение в partition 0 DLQ.

## Playwright

Конфигурация и сценарии находятся в `ui/e2e`; [инструкция запуска](e2e/README.md).
Основной набор сам собирает UI и поднимает preview на 127.0.0.1:4173. Он
проверяет настоящий DOM/CSS и поведение браузера, перехватывая все запросы API
для изоляции данных. Непредусмотренные API-запросы и ошибки JavaScript роняют тест.
Обычные Node/React-тесты и серверная регрессия запускаются отдельно.

Для реального сервера есть `npm --prefix .\ui run test:e2e:live`: проверка входа
без авторизации и отдельный сценарий загрузки Inbox тестовым сотрудником с
проверкой успешного ответа поиска. Для второго нужны PW_USERNAME/PW_PASSWORD.
Отсутствие этих переменных явно отмечается как пропуск, а недоступный сервер
роняет live-набор. Доступность Chromium не зависит от расширения ChatGPT в IDEA.

26 проверок с подготовленными API не закрывают проверку серверных прав,
реальных конкурентных назначений и доставки сообщений в Telegram. Таблица
ниже относится к оставшейся приёмке на реальном сервере.

## Оставшаяся приёмка на реальном сервере

Нужны два сотрудника и супервизор одного тестового Workspace, администратор,
второй Workspace для проверки изоляции, подключённый тестовый канал и диалог
с историей более 100 сообщений. Отправку проверять на согласованном тестовом
получателе. Результаты каждого пункта отмечать после фактической проверки.

| Сценарий | Что проверить | Статус |
| --- | --- | --- |
| Области, группы, фильтры | «Мои / Другие / Все», группа, сохранение и сброс фильтра, переходы назад/вперёд; выбранный фильтр сохраняется при смене области | Не выполнен |
| Группы | Создание, значок, переименование, удаление, изменение состава; чужие личные группы недоступны | Не выполнен |
| История и отправка | Страницы истории без дублей, прокрутка, черновики, текст/фото/аудио, доставка, ошибка и повтор | Не выполнен |
| Подробности клиента | Аккаунт без клиента, поиск, создание, привязка/отвязка, обновление шапки и фильтрованного списка, повтор ошибок | Не выполнен |
| Назначение | Сотрудник берёт свободный и освобождает свой; супервизор назначает/снимает любого участника своего Workspace; администратор действует в своей Organization | Не выполнен |
| Конфликт и потеря доступа | Два одновременных «Взять», переназначение открытого/ещё не открытого диалога, отказ изменения группы; список и права отправки обновляются | Не выполнен |
| Ошибки и переходы | 403/404 скрывают недоступные данные, 503 сохраняет доступные; A → B → A и смена Workspace не принимают старые ответы | Не выполнен |
| Адаптивность | Узкий экран, открытие/закрытие меню, клавиатура и фокус, скрытая переписка, остановка опроса | Не выполнен |

Подробные шаги: [переписка](INBOX_MESSAGES.md),
