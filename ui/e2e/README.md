# Браузерные проверки Inbox

Playwright запускается из терминала IDEA или обычного PowerShell. Расширение
Chrome для ChatGPT не требуется.

## Установка

Из корня проекта:

```powershell
npm --prefix .\ui ci
cd ui
npx playwright install chromium
```

После этого вернуться в корень проекта. Версия Chromium связана с Playwright
из `package-lock.json`; после обновления зависимости повторить установку браузера.

## Основной набор

```powershell
npm --prefix .\ui run test:e2e
```

Playwright сам собирает UI и поднимает preview на `http://127.0.0.1:4173`.
Этот порт должен быть свободен. Запускаются настольный и мобильный Chromium,
по два независимых теста одновременно. Каждому сценарию выделяются новые
браузерный контекст и данные.

Это браузерные проверки настоящей production-сборки React с подготовленными
ответами API. Они проверяют DOM, CSS, клики, клавиатуру, навигацию, состояния
ошибок и запросы UI. Все запросы `/api/` перехватываются, неизвестный запрос
роняет тест. Рабочий сервер и БД для основного набора не нужны.

Покрытие: сохранение выбранного фильтра при смене области, очистка, изменение
личного фильтра и сохранение системного себе; создание/переименование/значки
групп и отказ изменения membership; первоначальные 403/404, временный 503;
черновик при отказе отправки, создание клиента без потери черновика; UI ролей
сотрудника/супервизора/администратора; видимость нижних действий редактора,
Escape/возврат фокуса и отсутствие горизонтального переполнения.

Ответы API в этом наборе не подтверждают серверные ACL, транзакции, отправку
в Telegram или взаимодействие реальных пользователей. Эти проверки входят
в серверную регрессию и оставшуюся приёмку [10.10](../INBOX_ACCEPTANCE.md).

## Окно браузера, отладка и отчёт

```powershell
npm --prefix .\ui run test:e2e:headed
npm --prefix .\ui run test:e2e:ui
npm --prefix .\ui run test:e2e:report
```

Один проект или сценарий:

```powershell
npm --prefix .\ui run test:e2e -- --project=desktop-chromium
npm --prefix .\ui run test:e2e -- --grep "черновик"
```

При падении сохраняются снимок экрана и trace в `ui/test-results`, HTML-отчёт —
в `ui/playwright-report`. Ссылка на trace выводится в терминале. Эти каталоги
исключены из Git. Проверка типов конфигурации, фикстур и сценариев:

```powershell
npm --prefix .\ui run test:e2e:types
```

## Изолированная приёмка с настоящим backend

`InboxBrowserAcceptance` запускает Spring Boot на случайном HTTP-порту с
тестовыми PostgreSQL и Kafka, затем Playwright в настольном и мобильном Chromium.
Запросы успешных операций и проверки прав проходят через настоящий сервер,
JWT и БД; только в сценарии сетевой ошибки прерывается транспорт запроса.
Рабочая БД и подключённые пользовательские каналы не используются.

Из корня проекта, после установки npm-зависимостей и Chromium:

```powershell
npm --prefix .\ui run build
mvn -o -pl server -am '-Dtest=InboxBrowserAcceptance' '-Dsurefire.failIfNoSpecifiedTests=false' test-compile surefire:test
```

Нужен Docker и закешированные зависимости Maven/образы тестовых контейнеров
(те же требования, что у серверной интеграционной регрессии). Не запускать
параллельно с другими Maven-интеграционными тестами: общая база использует порт
15432 и фиксированные имена контейнеров.

20 сценариев (10 на каждом размере) проверяют вход по прямому `/login`, группы
и их приватность, сохранённые фильтры и историю браузера, создание/поиск/связь
клиента с сохранением черновика, роли и назначения, потерю/восстановление доступа,
одновременные «Взять» в двух независимых браузерных контекстах, очистку membership
при переназначении, 403/404, сетевой сбой, историю из 125 сообщений, изоляцию
Workspace/Organization, запоздалые ответы A → B → A и смены Workspace, паузу
опроса скрытой мобильной переписки. HTTP 503 вводится как отдельный
сбой транспорта; успешные ответы для задержанных запросов берутся у backend.
Свойства `document` не подменяются. Нативное скрытие вкладки требует отдельной
проверки в обычном браузере: используемый headless Chromium сохраняет её
`visibilityState=visible` даже при переключении страниц/сворачивании окна.
Для каждого сценария создаются отдельные организация, Workspace,
пользователи и диалоги.

Класс намеренно называется без суффикса `Test`: обычный серверный прогон не
требует установленного браузера. Прямой запуск `playwright.acceptance.config.ts`
без созданного стендом manifest завершается ошибкой. Временный manifest с
учётными данными находится в `server/target` и удаляется при завершении прогона;
данные авторизации и trace не сохраняются в отчёт.

Лог — `server/target/inbox-browser.log`, HTML-отчёт —
`server/target/inbox-browser-report/index.html`, снимки падений —
`server/target/inbox-browser-results`. Папки находятся вне отчёта основного
UI-набора и не затираются его запуском. Spring-контекст и контейнеры закрываются
после проверки.

Этот стенд не проверяет фактическую доставку сообщений внешнему получателю.
Для неё нужны подключённый канал, разрешённый тестовый получатель и проверка
текста/фото/аудио, статусов и повтора на настоящем соединении.

## Подключённый реальный сервер

Запустить backend отдельно и выполнить:

```powershell
npm --prefix .\ui run test:e2e:live
```

По умолчанию проверяется `http://localhost:8080`: настоящий UI без подмены API,
переход неавторизованного пользователя на форму входа. Отдельный сценарий входа
и загрузки Inbox выполняется при наличии данных тестового сотрудника:

```powershell
$env:PW_BASE_URL = 'http://localhost:8080'
$env:PW_USERNAME = 'test-employee'
$env:PW_PASSWORD = '<пароль тестового сотрудника>'
npm --prefix .\ui run test:e2e:live
```

Сотруднику нужен доступ хотя бы к одному тестовому Workspace. Пустой список
диалогов допустим. Открытие диалога может отметить сообщения прочитанными;
использовать тестовые данные. Сценарий не создаёт пользователей, не назначает
права и не отправляет сообщения. Если переменные входа не заданы, сценарий
входа явно отмечается как пропущенный; недоступный сервер приводит к падению,
а не подменяется фикстурой. `PW_BASE_URL` применяется только к live-набору.

Авторизация берётся из переменных окружения. Отчёты и локальные файлы состояния
авторизации не добавляются в Git. Основной набор не требует учётных данных.

## Совместный прогон

```powershell
npm --prefix .\ui test
npm --prefix .\ui run test:e2e:types
npm --prefix .\ui run test:e2e
mvn process-resources
```

Node/React-тесты из `ui/tests` и браузерные сценарии из `ui/e2e` запускаются
отдельными командами. Перед переносом ресурсов UI уже собран основным набором.
