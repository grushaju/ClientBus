# Inbox: декомпозиция этапа 10.6

## Границы

- `InboxPage` подключает `InboxWorkspace`.
- `InboxWorkspace` читает Auth/Workspace, сохраняет существующую компоновку
  `InboxLayout` и связывает навигацию, фильтры, группы и список.
- Внутренняя область списка пересоздаётся при смене Workspace, пользователя или
  прав. Формы, выбранный фильтр и ответы прошлой области не переносятся в новую.
- `ConversationView` остаётся вне этой пересоздаваемой области: существующая
  переписка сама определяет Workspace по маршруту диалога.
- `ConversationList` содержит только слоты интерфейса. DOM-обёртки, CSS и
  расположение элементов сохранены. Выделенная `InboxNavigation` подготовлена
  для дальнейшего переноса в отдельную колонку по HTML-макету.

## Запросы и обновления

`InboxSelection` исключает состояние GROUP без идентификатора группы.
`conversationFilterModel` преобразует применённые условия в запрос или
сохраняемое определение. Исходное определение выбранного фильтра больше не
подмешивается повторно; очищенные поля действительно очищаются. Ограничения
`clientAccountIds` сохраняются при восстановлении фильтра.
При переключении представления или группы, в том числе через историю браузера,
не редактируемые в текущем UI ограничения `clientAccountIds` сбрасываются вместе
с выбором сохранённого фильтра; видимые условия поиска, каналов, дат и сортировки
сохраняются. Намеренный переход при применении сохранённого фильтра сохраняет
его собственные условия. Отсутствующий `view` трактуется как MINE, как на backend.

В редакторе активности используются поля `date`, без времени. `filterDates`
преобразует дату «с» в начало выбранного дня, дату «по» — в его включительный
конец с точностью PostgreSQL. Используется локальный часовой пояс браузера;
длина дня учитывает переходы летнего времени. Сохранённые timestamps переводятся
в локальные календарные даты, затем применяются как границы полных дней.
До применения проверяются корректность дат и порядок границ периода.

Начальная загрузка каталогов групп и фильтров объединяется с успешными записями,
выполненными во время запроса: старый GET не стирает созданное, не отменяет
переименование и не восстанавливает удалённую группу. Смена выбранной группы
закрывает открытый редактор переименования предыдущей группы.

Загрузка всех страниц по 10 записей сохранена. Сервер определяет порядок;
клиент больше не перекрывает ASC сортировкой DESC. После событий обновления
диалога в текущем Workspace и успешного изменения membership список повторно
запрашивается, чтобы сервер пересчитал соответствие условиям. Повторная загрузка
той же выборки выполняется в фоне: карточки и меню остаются смонтированными.
При ошибке обновления карточки сохраняются, рядом отображается ошибка и кнопка
«Повторить». Первичная ошибка также допускает повтор. «Применить» и «Сбросить»
запускают запрос даже при неизменившихся условиях.

Устаревшие ответы не публикуются. При смене условий следующий запрос не
показывает карточки предыдущей выборки. Каналы остаются доступны в редакторе
условий во время повторной загрузки в том же Workspace.

API, правила видимости вкладки «Все», серверная авторизация, расположение
интерфейса и механизм выбора первого диалога сохранены. Переход к колонкам
макета, модальным формам и загрузке страниц по требованию в эту работу не входит.

## Проверки

Из `ui`:

```text
npm run test:inbox
npm run build
```

Тесты выполняются встроенным Node test runner, TypeScript и React test renderer.
Проверяются URL/права, преобразования фильтров, значки, пагинация, обогащение
данных, ошибки и отмена публикации устаревших результатов. Тесты React монтируют
`InboxWorkspace` с настоящими hooks и секциями: проверяются повторные запросы,
фоновые обновления без размонтирования карточек, сброс скрытых ограничений,
CRUD групп, membership, поздние ответы каталогов, переходы истории, часовые
пояса, неверные диапазоны дат и смена Workspace с незавершёнными запросами.
API и переписка заменены тестовыми реализациями.
Они не заменяют браузерную проверку CSS, прокрутки и взаимодействия с backend.

Ручная приёмка после запуска:

1. Открыть прямые ссылки mine/unassigned/group, перейти в диалог, проверить
   Back/Forward и сохранение groupId после создания диалога.
2. Создать группу с выбранным значком, переименовать, изменить membership,
   убрать диалог из активной группы и удалить группу.
3. Применить сохранённый фильтр; очистить поиск, каналы и даты; применить и
   сохранить копию. Проверить оба порядка сортировки.
4. Быстро менять условия и Workspace: предыдущие ответы не должны заменять
   новую выборку; формы и условия предыдущего Workspace должны сбрасываться.
5. Открыть непрочитанный диалог с активным фильтром непрочитанности, проверить
   обновление списка после прочтения и после назначения/освобождения.
6. Проверить обычного сотрудника, руководителя Workspace и SuperAdmin:
   вкладку «Все», личные группы и тип создаваемого фильтра.
