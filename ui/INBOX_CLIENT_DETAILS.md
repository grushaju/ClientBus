# Inbox 10.8 — подробности диалога и клиента

Реализация и автоматические проверки выполнены. Остаётся браузерная приёмка.
Схема БД и контракты API сохранены.

## Состояния панели

- Текущий аккаунт отображается независимо от наличия клиента: имя, значок платформы,
  username и телефон. Отсутствующие контактные поля не выводятся; username получает
  ровно один `@` в панели, шапке диалога и выборе аккаунта.
- Для привязанного клиента показываются имя, аватар, телефоны и признак неактивности.
  Список остальных доступных аккаунтов можно раскрыть отдельно.
- Отсутствие клиента не подменяет ошибку загрузки. Ошибки клиента, списка аккаунтов,
  метаданных текущего аккаунта и канала имеют отдельный повтор запроса.
  Ошибка списка аккаунтов не скрывает уже загруженного клиента.
- Канал показывает название, платформу и заполненные поля аккаунта канала.
  Пустые username/телефон не оставляют отдельные строки с символами `@` или `☎`.

## Команды и API

| Действие | API |
| --- | --- |
| Создать клиента из диалога | `POST /api/clients/from-conversation/{conversationId}` |
| Найти существующего клиента | `GET /api/clients/search?query=...` |
| Привязать текущий или дополнительный аккаунт | `POST /api/clients/{clientId}/clientaccounts/{accountId}` |
| Отвязать текущий аккаунт | `DELETE /api/clients/{clientId}/clientaccounts/{accountId}` |
| Загрузить доступные аккаунты клиента | `GET /api/clients/{clientId}/clientaccounts` |
| Найти аккаунт без клиента | `GET /api/clientaccounts/unassigned/search?query=...` |

- Создание и первоначальная привязка выполняются существующим транзакционным
  серверным методом. UI больше не создаёт клиента отдельным запросом перед привязкой.
- Команды доступны сотруднику и SuperAdmin в пределах действующих серверных проверок
  Organization и доступности диалогов/аккаунтов. Повторная привязка к тому же клиенту
  теперь также проверяет доступ к аккаунту перед возвратом DTO.
- Повторное нажатие во время команды блокируется синхронно. Ошибка сохраняет поля
  формы или выбранного клиента. Успех команды сразу обновляет связь; ошибка последующего
  чтения подробностей не превращает её обратно в состояние «Без клиента».
- Поиск клиентов и аккаунтов выполняется с задержкой 250 мс. При новом запросе старые
  результаты скрываются; отменённые ответы и ошибки не заменяют актуальные результаты.
- Привязка/отвязка обновляет шапку и публикует изменение списку диалогов, чтобы заново
  применились условия «С клиентом / Без клиента» и выбранные клиенты/аккаунты.
  Переписка и редактор сообщения не размонтируются, черновик сохраняется.
- Открытие другого диалога или изменение связи создаёт новую сессию панели. Поздние
  ответы, в том числе после A → B → A, не меняют её. Старые чтения метаданных и списка
  аккаунтов не отменяют успешно выполненную команду. URL аватаров освобождаются;
  завершившаяся после закрытия загрузка аватара не создаёт новый URL.

## Проверить в браузере

1. Открыть диалоги с клиентом и без клиента. В обоих видны текущий аккаунт и канал;
   у связанного клиента видны телефоны, аватар и остальные доступные аккаунты.
2. В своём диалоге набрать черновик. Создать клиента, затем отвязать аккаунт:
   текст черновика и история остаются на месте. Проверить имя/фамилию из пробелов,
   двойное нажатие и отказ API — заполненные поля должны сохраняться.
3. Найти существующего клиента по имени или телефону и привязать аккаунт.
   Быстро сменить поисковую строку; результат предыдущего поиска не должен возвращаться.
4. Привязать ещё один аккаунт без клиента, раскрыть другие аккаунты. Проверить отказ
   привязки и отсутствие дублей при повторном нажатии.
5. Применить фильтр «С клиентом» или «Без клиента», изменить связь и проверить обновление
   списка диалогов. Проверить те же действия под сотрудником и SuperAdmin.
6. При медленной сети начать загрузку/команду и переключиться A → B → A.
   Подробности нового диалога не должны заменяться старым ответом.
7. Смоделировать ошибку чтения клиента, аккаунтов или канала и повторить загрузку.
   Ошибка не должна предлагать создание нового клиента для уже связанного аккаунта.

Изменения связи из другой вкладки перечитываются при повторном открытии диалога;
отдельного постоянного опроса карточки клиента в этом этапе нет. Проверка конкурентных
серверных изменений из разных сессий остаётся частью 10.9.
