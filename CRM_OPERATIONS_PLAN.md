# 12.6 — управление визитами

Работа начата 08.11.2026 по поручению пользователя «Пошли кодить 12.6».
Основание: Stage 12.txt, CRM_CONTRACTS.md (разделы 6–9), CRM_DIKIDI_PROTOCOL.md (W01–W04).

1. Добавить типизированный порт команд и доступности с закрытыми по умолчанию возможностями.
2. Создать долговечный журнал crm.operation: контекст, инициатор, ключ/хеш запроса, состояния REQUESTED/IN_FLIGHT/CONFIRMED/REJECTED/UNKNOWN. Защитить удаление автора.
3. Реализовать допуск создания/переноса/отмены, повтор по ключу до проверки нового контекста, атомарное право начать эффект и восстановление без повторной отправки начатой команды.
4. Добавить чтение/поиск/список операций и безопасную сверку, проверки текущих прав и ограничение активных изменений одного визита.
5. Добавить UI намерения/подтверждения и журнала; сохранять ключ до POST, после потери ответа выполнять lookup. UNKNOWN остаётся активным; повтор с новым ключом автоматически не создаётся.
6. Проверить транзакции и конкуренцию на PostgreSQL, HTTP-контракты, отмену/поздние ответы и восстановление UI; собрать UI и перенести ресурсы.
7. Для DIKIDI отдельно подтвердить W01–W04 на явно выделенных тестовых данных, затем реализовать/включить только доказанные команды и сверку. Метод remove не подменяет отмену; непроверенный payload переноса не отправляется.

09.11.2026 на выбранном пользователем тестовом аккаунте проверены и включены CREATE_APPOINTMENT, MOVE_APPOINTMENT и CANCEL_APPOINTMENT. Реальным Java-адаптером выполнен цикл: создание 18 ноября в 12:00 → перенос на 25 ноября в 12:00 → отмена (Europe/Moscow). Каждый результат подтверждён отдельным чтением DIKIDI. Все известные созданные проверкой визиты отменены. Отдельно проверена потеря ответа после сохранения: read-only сверка нашла созданный визит по заранее сохранённому ID, без второго резерва или сохранения. Персональные значения и реальные ID в документацию не включаются.

Поддержаны существующий PROJECT CRM-клиент, известные фиксированные услуги и один мастер. Перенос меняет только время при прежнем мастере; визиты с непустыми ресурсами отклоняются. Создание клиента, смена мастера, ресурсов и финансовые команды не реализованы. Комментарий к отмене сохраняется только в ClientBus. TTL/автоматическое освобождение незавершённого резерва не установлены: UNKNOWN не разрешает повторную отправку. Оплаченные, смешанные и ресурсные сценарии живым прогоном не проверялись. Кэш/защита от 429 — следующий подпункт 12.6.1; общая приёмка — 12.7.

Коммит и push без отдельного поручения не выполняются.
