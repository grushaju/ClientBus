# Бэклог

## Отправка сообщений DIKIDI от персонального оператора ClientBus

Статус: отложено. Полноценная реализация не входит в текущую правку интерфейса.

Сейчас канал использует учётные данные CRM-подключения проекта. Таблица «Профиль → оператор → сотрудник ClientBus» хранит соответствия, но не выбирает авторизованную сессию отправки. Рядом с таблицей показан аккаунт подключения с маскированным логином и пояснение этого ограничения.

### Требуемое поведение

- Автор сообщения в ClientBus определяет привязанного оператора DIKIDI в конкретном проекте. ID записи доступа кабинета и ID учётки оператора остаются разными идентичностями.
- Отправка выполняется из сессии, авторизованной именно учётными данными этого оператора. Подстановка ID автора в запрос не заменяет авторизацию.
- Учётные данные операторов хранятся зашифрованными; UI показывает состояние подключения и позволяет пройти необходимый вход без раскрытия секретов.
- Автор и выбранная идентичность отправителя фиксируются для принятой операции и проходят через очередь. Повторная обработка не переключает сообщение на другого оператора при изменении маппинга.
- Перед отправкой проверяются действующие права, проект и состояние авторизации. Отсутствие связи, неоднозначный маппинг или невозможность входа дают понятный отказ; автоматической отправки основным аккаунтом вместо выбранного оператора нет.
- Сохраняются существующие гарантии обработки неопределённого результата: отсутствие ответа после отправки не разрешает повторную внешнюю запись.
- Чтение канала и CRM-синхронизация сохраняют собственный контекст авторизации; добавление отправителей не создаёт дубли диалогов и не меняет общий аватар канала на фото последнего отправившего оператора.

### Этапы и предварительная оценка

| Этап | Оценка |
| --- | --- |
| Проверка входа двух операторов, доступа к одному проекту и чатам | 1–2 рабочих дня |
| Хранение секретов, подключение и состояние операторов | 2–3 дня |
| Передача автора через очередь, выбор сессии и защита повторов | 2–3 дня |
| UI, тесты и приёмка несколькими операторами | 2–4 дня |

Общий ориентир: 7–12 рабочих дней. Уточнить после проверки SMS, CAPTCHA, срока жизни сессий, правил доступа к чатам и ограничений одновременных входов DIKIDI. Значения таймаутов и лимитов должны настраиваться конфигурацией.

### Приёмка

Два сотрудника ClientBus отправляют сообщения от двух разных подтверждённых операторов DIKIDI. Проверяются отзыв прав, смена маппинга после постановки сообщения в очередь, повторная доставка задания, перезапуск, истечение сессии и потеря ответа на отправку. Проверки, отправляющие реальные сообщения, выполняются только по явному разрешению пользователя.
